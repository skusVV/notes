# 0013 - Швидка нотатка з iPhone (Action Button, тап по спині) + спільний вхід `/ingest`

> **READY** (власник, 2026-11-01). Критерії зафіксовано, назва ендпоінта - `/ingest/message`. Питання в
> кінці розділу "Відкриті питання" не блокують імплементацію: це перевірки на телефоні.

## Context

Зараз, щоб записати думку, треба відкрити Telegram, знайти чат і надиктувати голосове. Це 4-5 дій.
Цей спек дає **одну дію**: натиснув Action Button (або двічі стукнув по задній кришці), сказав фразу -
вона потрапила в бота і пройшла той самий шлях, що й повідомлення, набране в чаті (класифікатор,
збереження, відповідь у Telegram).

Технічно: iPhone-команда (Shortcut) шле `POST` на новий ендпоінт функції. Ендпоінт підписаний
**власним секретом**, не секретом Telegram-вебхука, бо це інший викликач (твій телефон).

Це також **фундамент для [0014](0014-calendar-sync.md) і [0015](0015-apple-health-sync.md)**: обидва
використовують той самий секрет, ту саму перевірку і ту саму прив'язку до користувача. Тому
спільна частина (`IngestGuard`) тут, а не дублюється.

Ідея і порівняння варіантів - у розмові від 2026-11-01; в [../architecture.md](../architecture.md)
цього ще немає.

## Рішення, прийняті в цьому спеку

1. **Той самий шлях, що й чат.** Тіло запиту перетворюється на синтетичне Telegram-оновлення і йде в
   `TelegramService.handleUpdate`. Нового класифікатора, нового маршрутизатора чи дубля логіки немає:
   `ALLOWED_USERS`, класифікація, збереження і відповідь працюють рівно так, як для чату.
2. **Відповідь - у Telegram**, як зазвичай (рішення власника). Команда на телефоні нічого не
   показує, окрім короткого "Надіслано".
3. **Один власник.** Користувач береться зі змінної `INGEST_USER_ID`, а не з тіла запиту. Телефон не
   може заявити "я інший користувач". Приватний чат Telegram має `chat.id == user id`, тому відповідь
   іде туди ж.
4. **Закрито за замовчуванням (fail closed).** Якщо `INGEST_SECRET` або `INGEST_USER_ID` не задані,
   ендпоінт відповідає `401`, як `/sweep` без `REMINDER_SWEEP_SECRET`
   ([../../CLAUDE.md](../../CLAUDE.md)). Не так, як вебхук Telegram, де порожній секрет пропускає перевірку.
5. **Лише текст.** Share sheet (посилання, скріншот) - окремий спек (див. Out of scope).

## Contracts

### `POST /ingest/message`

Заголовки: `X-Ingest-Secret: <INGEST_SECRET>`, `Content-Type: application/json`.
Тіло: `{ "text": "<рядок>" }`.

| Ситуація | Відповідь |
|---|---|
| секрет відсутній/хибний, або `INGEST_SECRET`/`INGEST_USER_ID` не задані | `401`, нічого не оброблено |
| `text` відсутній, не рядок, порожній після `trim`, або довший за `INGEST_MAX_TEXT_CHARS` (4000) | `400` `{ "ok": false, "error": "invalid_text" }` |
| все гаразд | `200` `{ "ok": true }` |

`400` тут допустимий (на відміну від вебхука Telegram): викликач - твоя команда, їй корисно побачити
помилку, а ретраїв Telegram тут немає. Але **збій обробки після валідації - це `200`**, залогований, а
не `5xx`, з тієї самої причини, що й у вебхуку.

На тестовій функції (`TEST_REFLECT_REPLY=true`) відповідь додатково містить `replies: string[]` і
шанує `X-Test-Now` - та сама межа довіри, що й у вебхука та `/sweep`. У проді обидва ігноруються.

Текст обробляється **так, ніби його набрали в чаті**, включно з тим, що рядок, який починається з `/`,
виконується як команда (`/version`, `/export`). Це зручно і безпечно: ендпоінт закритий секретом, а
користувач один.

### Синтетичне оновлення

`update_id` береться з годинника (унікальний на запит), `message_id` так само, `chat.id == from.id ==
INGEST_USER_ID`, `from.is_bot == false`, `text` - з тіла. `update_id` у коді використовується лише в
логах, тож колізії з реальними id Telegram нічого не ламають.

### Конфігурація

| Змінна | Звідки | Зміст |
|---|---|---|
| `INGEST_SECRET` | Secret Manager | Спільний секрет для всіх `/ingest/*`. Довгий випадковий рядок. |
| `INGEST_USER_ID` | `--set-env-vars` | Telegram user id власника. |
| `INGEST_MAX_TEXT_CHARS` | код, за замовч. 4000 | Ліміт довжини. |

## Налаштування на телефоні (текст для README, Cloud Console + iOS)

README отримує розділ, який можна виконати, не знаючи нічого про код:

1. **Секрет.** Console > Security > Secret Manager > Create secret: ім'я `INGEST_SECRET`, значення -
   випадковий рядок із 32+ символів. Дати `<PROJECT_NUMBER>-compute@developer.gserviceaccount.com` роль
   Secret Manager Secret Accessor на цей секрет. Додати `INGEST_USER_ID` у змінні деплою.
2. **Адреса.** Console > Cloud Run functions > `telegramBot` > вкладка Trigger > скопіювати URL
   функції. Повна адреса команди: `<URL>/ingest/message`.
3. **Команда.** iPhone > Команди > "+" > назва "Нотатка". Дії по черзі:
   1. **Диктувати текст** (мова: автовизначення, якщо є; інакше українська).
   2. **Отримати вміст URL**: URL = `<URL>/ingest/message`; Метод = POST; Заголовки: `X-Ingest-Secret` =
      секрет, `Content-Type` = `application/json`; Тіло запиту = JSON, поле `text` = змінна "Диктований
      текст".
   3. **Показати сповіщення**: "Надіслано".
4. **Прив'язка до кнопки** (одна з трьох):
   - **Action Button** (iPhone 15 Pro і новіші, усі 16 і 17): Налаштування > Кнопка дії > Команда > обрати
     "Нотатка".
   - **Тап по спині** (iPhone 8 і новіші): Налаштування > Універсальний доступ > Дотик > Тап по задній
     панелі > Подвійний тап > "Нотатка". Товстий чохол може заважати або давати помилкові спрацювання.
   - **Віджет на екрані блокування** і голос: "Привіт, Siri, Нотатка" працює для будь-якої моделі.
5. **Перевірка.** Запустити команду, сказати "тест нотатки", відповідь має прийти в Telegram.
6. **Безпека секрету.** Секрет лежить усередині команди. Не діліться командою через iCloud-посилання. Якщо
   телефон загублено: створити нову версію секрету в Secret Manager, оновити команду, задеплоїти.

## Invariants (must not break)

- Вебхук Telegram завжди `200`, окрім хибного секрету (`401`). `/ingest` цього контракту не змінює.
- Гейт `ALLOWED_USERS` виконується **перед** будь-яким викликом моделі: синтетичне оновлення проходить
  через `handleUpdate`, тож гейт діє автоматично. Не обходити його спеціальним шляхом.
- Секрет порівнюється за сталий час, у логах - лише довжини, ніколи самі значення.
- Тексту нотаток немає в логах (дисципліна для даних про здоров'я, [../../CLAUDE.md](../../CLAUDE.md)); логується лише user id.
- Відповіді без `parse_mode`; усе, що надсилається назовні, іде через `sendMessage` з чанкуванням.

## Acceptance criteria (locked at READY)

Припущення верифікатора: на тестовій функції `INGEST_USER_ID` = U1 (`900000001`, один із шести дозволених тестових id), задано
`INGEST_SECRET` і `TEST_REFLECT_REPLY=true`.

- **health:** `GET /` повертає `200` і `{"status":"ok"}`.
- **ingest-no-secret:** `POST /ingest/message` без `X-Ingest-Secret` повертає `401`; нічого не збережено.
- **ingest-wrong-secret:** `POST /ingest/message` з хибним секретом повертає `401`.
- **ingest-empty-text:** з валідним секретом `{"text":"   "}` повертає `400` з `error == "invalid_text"`.
- **ingest-too-long:** з валідним секретом `text` довжиною 4001 повертає `400`.
- **ingest-command-passthrough:** `{"text":"/version"}` з валідним секретом повертає `200`, `ok == true`
  і `replies` містить рядок, що збігається з `/^notes-bot \d+\.\d+\.\d+$/` (доводить, що текст іде тим
  самим шляхом, що чат, включно з маршрутизацією команд).
- **ingest-note-stored:** `{"text":"Нотатка: код від гаража 4471"}` з валідним секретом повертає `200`;
  `replies` непорожній (це відповідь, що пішла б у Telegram); `/export` від U1 містить збережений запис,
  текст якого має `4471`. Перевірка за збереженою структурою, не за формулюванням відповіді.
- **webhook-unchanged:** `POST /` з хибним `X-Telegram-Bot-Api-Secret-Token` досі повертає `401`, а з
  валідним - `200`.
